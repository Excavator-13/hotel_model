## Context

仓库目前只有 OpenSpec 初始化文件，没有实现、测试或既有技术栈。动机见 `proposal.md`；行为契约见 `specs/hotel-preference-training/spec.md`。用户已选择终端交互，原始数据采用明确的八项输入，主要考虑舒适、半高档、高档。

本设计包含新增数据契约、数值优化依赖、交互标注和恢复状态，满足编写设计文档的条件。此前讨论中的公式和数量是建议，本变更将固定一套可实现、可验证的 v1 默认值。

## Goals / Non-Goals

**Goals:**

- 以八维可解释特征、凸优化和简单主动选题支持少量个人判断。
- 数据和模型配置不随城市或候选池改变，使不同训练会话的权重含义一致。
- 记录先保存、拟合后更新，中断或拟合失败后可以继续。
- 将数值逻辑与输入输出分开，便于验证标签方向、选题和恢复契约。

**Non-Goals:**

- 不学习非线性曲线、档次专属增量、交互项、城市系数或多人偏好。
- 不实现生产评分、排名、推荐、网页、爬虫或地图查询；内部计算酒店得分仅用于训练和选题。
- 不做自动超参数搜索、交叉验证命令、概率校准或自动停止判定。
- 不支持已有会话中改样本、增补样本、修改答案或重新打开跳过题。需要这些行为时开启新状态文件，未来另行扩展。

## Decisions

### 1. 使用 Python 终端程序与本地文件

实现建议为 Python 3.11+，标准库 `csv`、`json`、`argparse` 负责文件和终端；NumPy 负责向量计算，SciPy 负责优化；pytest 用于测试。项目使用 `pyproject.toml` 和 `src/hotel_model/`。按数据、特征、拟合、选题、状态、终端职责拆分小模块，不引入插件架构。

拟定入口：

```text
hotel-model train --data hotels.csv --state session.json --seed 42 --l2 0.1
hotel-model train --resume session.json
hotel-model train --resume session.json --data hotels.csv
```

新建会话必须显式指定数据和输出状态；已有输出文件拒绝覆盖。恢复从快照读取数据，可选 CSV 只用于一致性校验。恢复时不允许修改训练或选题配置。`--help` 展示说明，终端问题展示原始数值及单位，用户输入 `a/b/t/s/q`。

替代方案：网页增加前端和服务成本；数据库对单用户小样本不是必要依赖；手写优化器增加数值风险。本阶段选用单进程本地程序。

### 2. CSV 保留原始数据，严格验证

列与范围以规格为准。支持 UTF-8 和 UTF-8 BOM，首尾空白规整，额外列忽略且不进入模型；必需列重复时拒绝。校验完成前不创建训练状态。原始记录按稳定 ID 关联，ID 表示具体房型样本，而不是允许价格任意变化的酒店实体。

未来 README 和模板可以使用如下原始数据例子；这是格式示例，不是真实酒店信息：

```csv
hotel_id,name,city,grade,renovation_age_years,ctrip_rating,subway_walk_minutes,mall_transit_minutes,attraction_taxi_minutes,room_area_sqm,nightly_price
hz-01,示例舒适酒店,杭州,3,2,4.7,6,15,22,25,320
hz-02,示例半高档酒店,杭州,4,5,4.6,12,8,18,30,380
hz-03,示例高档酒店,杭州,5,3,4.8,9,20,25,35,480
```

价格暂按人民币含税每晚总价理解，入住人数、日期、早餐和退订条件由用户整理成可比口径；第一版不增加日历或套餐字段。不同比较城市可以采用各自旅行日期，但同一次比较的条件必须可比。目标景点采用本次旅行固定集合，各酒店按同一集合取平均打车时间。装修年数直接读取文件值，不随系统时间自动变化。

替代方案：缺失填补和缺失指示特征会增加假设及参数；小样本优先手动补齐，第一版遇到缺失拒绝读取。

### 3. 八项固定变换与非负权重

特征顺序和 v1 公式见规格。评分以 4.7 为中心、0.2 为尺度，适合用户提到的 4.6 至 4.8 常见范围；价格中心为 300，面积中心为 25。中心常数在同城差分时抵消，主要改善解释和数值尺度，不表示价格预算线。

三类时间分别有独立权重，虽然变换均为 `-log1p(minutes / 5)`，不假设步行、公共交通和打车的主观成本相同。装修年数在 15 年封顶，体现非常旧之后区分度降低；保存原始年数，截断只用于特征。正向指标和已取负号的成本指标全部搭配 `w >= 0`，形成单调偏好先验。

档次使用 `grade - 4` 的单一特征，九级之间等距。舒适到高档的比较不能证明奢华档的边际价值也相同，暂不增加八个档次阈值参数。不能从几乎相同档次的样本估计出有意义的档次权重。

替代方案：逐城市标准化改变每个单位的取舍含义；原价线性惩罚不符合已确认的价格偏好；自由权重在少量相关数据下容易出现反向作用；分段变换和独热档次增加参数。v1 使用固定曲线和方向约束作为可调整的设计假设，曲线变化必须提升预处理版本。

### 4. 使用带约束的成对逻辑回归

对展示顺序中的 A、B，定义 `d = zA - zB`，严格标签为 1 或 0，平局为 0.5。所有城市的有效比较合并：

```text
v_i = w dot d_i
p_i = sigmoid(v_i)
loss(w) = mean(logaddexp(0, v_i) - y_i * v_i)
          + lambda / 2 * (w dot w)
subject to w_j >= 0
```

使用 SciPy L-BFGS-B、解析梯度和稳定 sigmoid，从最近成功的权重开始，每次用全部有效标签重拟合。默认 `lambda=0.1`，可在创建会话时改为其他有限正数，恢复时固定；梯度为 `mean((p-y) * d) + lambda*w`。平均损失使默认正则强度不随标签数机械改变。

L2 使完全可分数据仍具有有限解；该目标支持单个严格标签、单一胜负方向以及全平局。尚无有效标签时初始化零向量但标记 `untrained`；全平局对应有效的零权重解。不要采用要求硬标签或两类标签的通用分类器接口。

优化器返回成功且权重、损失均有限时才接受结果；否则保留最近成功的权重、标记覆盖标签数落后、报告失败并暂停。恢复时先拟合未覆盖的标签，再继续提问。训练交叉熵不含正则项，不等同于验证误差或校准度。

替代方案：对胜负直接做最小二乘会人为指定目标分差；复杂排序模型和贝叶斯后验超过当前需求；零正则不能稳定处理完全可分的小样本。

### 5. 轻量主动学习兼顾不确定性、差异和覆盖

枚举各城市内的无序对，按城市和 ID 排序保证稳定顺序，移除已回答、已跳过及特征差异范数不超过 `1e-9` 的对。城市只有一个样本时不产生候选。无需先选择城市；从合并的合法候选中选择，因此不保证每个城市获得等量问题。

每次以会话随机生成器进行 20% 概率的随机探索，从全部合法候选均匀选取。其余分支若存在取舍对，即差向量同时包含大于 `1e-9` 和小于 `-1e-9` 的分量，优先在取舍对中选择；否则回退到全部候选。

非探索分支的确定性打分如下：

```text
d = zA - zB
M = min(norm(d) / sqrt(8), 1)
u = d / norm(d)
D = 1 - max(abs(dot(u, historical_unit_difference)))
U = 4 * p * (1 - p)
cold_score = 0.6 * M + 0.4 * D
active_score = U * (0.5 + 0.5 * M) * (0.5 + 0.5 * D)
```

历史方向覆盖所有已回答和跳过的非零差向量；无历史时 `D=1`，浮点误差后将 D 截到 `[0,1]`。有效标签少于 8 时使用冷启动分数，之后用主动分数。分数相同时按稳定候选顺序选择，最后再随机交换展示 A、B。由于使用方向内积绝对值，交换历史 A、B 不改变覆盖计算。

这是易验证的选题启发式，不是权重后验不确定性估计。它降低几乎相同样本和重复取舍的优先级，随机探索保留其他候选的机会。常数作为选题版本 `v1` 保存。恢复必须还原随机状态和待答题，不能重新抽取左右顺序。

替代方案：纯 50% 不确定性会偏向近似相同的酒店；纯随机浪费部分问题；后验采样和 Fisher 信息方法增加复杂度，留待真实使用数据支持时再讨论。

### 6. 一个 JSON 检查点是训练事实来源

状态保存 `schema_version`、经过验证的原始样本快照、样本内容指纹、预处理版本和常数、正则及选题配置、种子及随机生成器状态、待答问题、答案事件序列和最近成功模型。模型记录权重、训练标签覆盖数、训练损失和优化状态；未训练时损失为空。

指纹计算使用规整后的必需字段，按 ID 排序、稳定序列化后做 SHA-256；CSV 行顺序、BOM 和无关额外列不影响语义一致性，必需字段变化影响指纹。恢复不接受不兼容版本，且验证记录引用、同城约束、标签、非重复样本对、权重长度和有限值等不变量。

状态更新使用同目录临时文件与原子替换。生成题目后先保存待答题及抽取后的随机状态，再展示；收到答案后先追加事件并清除待答题、原子保存，再拟合及保存模型。第二步失败时事件已保留，覆盖数体现旧模型状态；下一次恢复先重拟合。保存失败则停止，不继续累积未持久化判断。

`q`、EOF、Ctrl-C 不为待答题产生答案；恢复重新显示该待答题。跳过也永久从本会话候选中移除。程序按单进程使用设计，不支持多个进程同时编辑同一状态；README 提醒单个状态只运行一个训练进程。

不另建面向使用的模型导出或评分入口；检查点中的版本化参数已经满足训练成果保存要求。

### 7. 诊断以可观察事实为主

打印规格要求的计数、共享权重、覆盖状态和训练交叉熵；检查各特征在有效比较中的差值是否始终近似零，列出没有比较信息的维度。权重仅解释为固定变换下的系数，不是因果作用或“重要性百分比”。不实现共线性统计检验或自动识别完整的权重可辨识性。

README 建议一个城市先选 16 家：半舒适 2、舒适 4、半高档 4、高档 4、半豪华 2。数量不是程序限制；优先真实有可能选的酒店，特别是价格接近但档次不同、新旧与价格有取舍的组合。经济及豪华以上无需为了配额加入。多个城市共用相同数据口径和固定变换，但跨城市效果需要未来独立判断验证。

## Risks / Trade-offs

- [相关特征让权重难以区分] -> 使用 L2 和方向先验稳定结果，采样时寻找属性没有同步变化的酒店，避免过度解释权重。
- [档次等距及固定曲线可能偏离真实偏好] -> 明确这是 v1 假设，保存完整原始数据和变换版本，未来变更需要新会话或显式迁移。
- [共享权重不保证迁移] -> 不训练城市系数，不比较跨城市酒店，不宣称已验证；后续另行设计留出城市的评估。
- [不同出行目的改变取舍] -> 第一版以单个人、稳定旅行偏好为假设，保持训练样本的目标景点和入住条件可比。
- [主动选题带来选择偏差] -> 保留 20% 随机探索，训练损失仅作为拟合诊断，不估计全体酒店上的泛化误差。
- [差异幅度和覆盖是启发式] -> 公式固定并测试，避免承诺最少标注次数或精度指标。
- [候选枚举为城市内平方复杂度] -> 面向几十家样本可以接受；不在本版引入大规模候选索引。
- [状态写入或优化被中断] -> 采用原子检查点、先记录答案再拟合、覆盖计数和待答题恢复。

## Migration Plan

当前没有既有模型或数据格式，无需迁移。实现后以本地安装、示例 CSV 和新会话启动；验证中断恢复及样本指纹保护。试用结束可以保留状态文件，回退代码不会改写原始 CSV；后续不兼容格式必须增加版本并显式处理，不能静默解释旧状态。
