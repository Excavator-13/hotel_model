# hotel-model

本地终端酒店偏好训练器。它用**同城两家酒店的两两比较**，训练一个**八维共享线性权重**模型，并把训练过程保存到本地 JSON 状态，中断后可以继续。

第一版只做训练：**没有**新酒店评分、推荐排序、网页或部署服务，也不联网。

---

## 1. 安装

需要 Python 3.11+。本仓库用 **conda** 管理环境，依赖清单见 [`environment.yml`](environment.yml)。

```bash
conda env create -f environment.yml
conda activate hotel-model
hotel-model --help
```

`environment.yml` 会创建名为 `hotel-model` 的环境，安装 NumPy、SciPy、pytest，并以可编辑模式安装本包。若 `defaults` 频道要求接受 Anaconda 服务条款，可用：

```bash
CONDA_PLUGINS_AUTO_ACCEPT_TOS=yes conda env create -f environment.yml
```

已创建过环境时，修改依赖后更新：

```bash
conda env update -f environment.yml --prune
```

> **不要用 conda `base` 环境跑本项目。** 本项目只在专用环境里验证过；`base` 里可能已有损坏或不兼容的 NumPy。
>
> 没有 conda 时可用 venv 作为备选：`python3 -m venv .venv && .venv/bin/python -m pip install -e ".[test]"`。

`--help` 只包含训练入口 `train`。

## 2. 快速开始

下面用 `conda run -n hotel-model` 直接调用环境里的命令（脚本里最省事）；交互使用时先 `conda activate hotel-model` 再去掉前缀。

```bash
# 新建会话（必须显式给出数据和状态文件）
conda run -n hotel-model hotel-model train --data examples/hotels_example.csv --state session.json

# 退出后继续同一个会话
conda run -n hotel-model hotel-model train --resume --state session.json

# 恢复时可选地提供 CSV 做一致性校验
conda run -n hotel-model hotel-model train --resume --state session.json --data examples/hotels_example.csv
```

参数：

| 参数 | 说明 |
|---|---|
| `--data` | 原始酒店 CSV；新建时必需，恢复时可选（仅用于校验快照是否一致） |
| `--state` | 训练状态 JSON 路径；**`--resume` 也必须给出**（没有位置参数形式） |
| `--resume` | 从已有状态文件恢复 |
| `--seed` | 随机种子，默认 `42`；仅在新建会话时生效 |
| `--l2` | L2 正则强度，默认 `0.1`，必须是有限正数；仅在新建会话时生效 |
| `--quiet` | 结束后不打印诊断 |

新建会话**不会覆盖**已存在的状态文件。恢复时训练与选题配置固定，`--seed`/`--l2` 被忽略（沿用状态文件中的值）。

## 3. 输入数据（CSV）

原始 CSV 必须是 UTF-8（可带 BOM）。空模板见 [`examples/hotels_template.csv`](examples/hotels_template.csv)，**全部虚构**的完整示例见 [`examples/hotels_example.csv`](examples/hotels_example.csv)。

必需列共 11 个：

| 列 | 含义与单位 | 校验 |
|---|---|---|
| `hotel_id` | 样本 ID，代表**一个具体酒店房型**，不是可任意改价的酒店 | 非空且文件内唯一 |
| `name` | 展示名称 | 非空 |
| `city` | 城市 | 非空 |
| `grade` | 档次，1–9 的整数 | 必须是整数且在 1–9 |
| `renovation_age_years` | 装修年数（年），**直接读取文件值** | 非负 |
| `ctrip_rating` | 评分 | 0–5 |
| `subway_walk_minutes` | 到最近地铁站的**步行**分钟 | 非负 |
| `mall_transit_minutes` | 到最近大商场的**公共交通**分钟 | 非负 |
| `attraction_taxi_minutes` | 到目标景点的**平均打车**分钟 | 非负 |
| `room_area_sqm` | 房间面积（平方米） | 大于零 |
| `nightly_price` | 每晚价格（人民币元） | 大于零 |

九档名称：1 经济、2 半舒适、3 舒适、4 半高档、5 高档、6 半豪华、7 豪华、8 半奢华、9 奢华。

额外列会被忽略；必需列重复、缺失、`NaN`/`inf`、越界、重复 ID 或空标识都会在**创建状态之前**拒绝整份数据，并报告可定位的行号与字段名。**不做缺失填补**，遇到缺失请先手动补齐。

## 4. 预处理公式（版本 `v1`）

固定顺序的八维特征，**不做逐城市或逐样本池归一化**：

| 特征 | 变换 |
|---|---|
| `grade` | `grade - 4` |
| `renovation` | `-min(renovation_age_years, 15) / 5` |
| `rating` | `(ctrip_rating - 4.7) / 0.2` |
| `subway` | `-log(1 + subway_walk_minutes / 5)` |
| `mall` | `-log(1 + mall_transit_minutes / 5)` |
| `attraction` | `-log(1 + attraction_taxi_minutes / 5)` |
| `area` | `log(room_area_sqm / 25)` |
| `price` | `-log(nightly_price / 300)` |

成本类特征已取负号，因此**所有八个权重都约束为非负**：某一维数值越高，另一维不变时得分不会下降。价格使用对数，所以 200→300 的涨幅比 800→900 更"令人在意"。中心常数（4.7 / 25 / 300）在同城差分时会抵消，只改善数值尺度与解释，**不表示预算线**。

## 5. 回答方式

程序只展示**同城**的两家酒店，并列出全部原始字段（含档次名称与单位）。输入（大小写和首尾空白不影响识别）：

| 输入 | 含义 | 记录 |
|---|---|---|
| `a` | A 更好 | 标签 `1`（按当前展示方向） |
| `b` | B 更好 | 标签 `0`（按当前展示方向） |
| `t` | 差不多 | 软标签 `0.5`（按平局参与训练） |
| `s` | 无法判断 | **跳过**，不计入损失 |
| `q` | 退出 | 不产生当前题目的答案 |

无效输入会保留当前题目且不产生记录。`q`、EOF（Ctrl-D）和 Ctrl-C 都会正常结束并**保留已保存的进度**；已保存的答案不会丢失。

同一训练会话中，已回答或跳过的无序样本对不会再问，交换 A/B 也不能绕过。

## 6. 比较条件

为了让标签有意义，比较时应保持条件可比：

- 价格与面积应对应**同一房型**；
- 使用**可比的入住日期、人数、早餐和退订条件**；
- 各城市可以有不同的旅行日期，但**同一次比较内**的条件必须可比；
- 景点打车时间采用本次旅行**固定的一组目标景点**，各酒店按同一集合取平均。

## 7. 采样指南（建议，不是配额）

建议一个城市先准备 **16 家**左右：

半舒适 2、舒适 4、半高档 4、高档 4、半豪华 2。

要点：

- 数量**不是程序限制**，也不强制档次配额；经济档与豪华以上无需为了凑数加入。
- 优先选择**真实可能入住**的酒店，特别是**价格接近但档次不同**、以及**新旧与价格互相取舍**的组合。
- 主动选题会用 20% 的随机探索保留意外组合，但数据本身的取舍结构决定了能学到什么。

## 8. 模型与训练

对展示顺序中的 A、B：`d = z_A - z_B`，`p = sigmoid(w · d)`，目标为

```text
loss(w) = mean(logaddexp(0, w·d) - y * (w·d)) + lambda/2 * (w·w)，  约束 w >= 0
```

- 八个权重由**所有城市共享**，无截距、城市参数或交互项。
- 每次收到有效标签后，用**已积累的全部有效标签**重新拟合（SciPy L-BFGS-B）。
- 平局使用软标签 0.5；只有一次严格判断也能拟合出有限、非负的权重。
- 拟合失败（优化器失败或结果非有限）时：**保留标签和最近成功的权重**，标注还有多少有效标签未被覆盖，并停止继续选题，直到下次恢复重新拟合成功。
- 选题：枚举同城无序对（排除已处理与特征相同的对）。有效标签少于 8 时用冷启动覆盖率打分，之后用「预测接近 0.5 × 差异幅度 × 取舍方向覆盖」的主动打分；存在双方各有优势的取舍候选时优先在其中挑选；每次选题有 20% 概率随机探索，左右展示顺序随机化。

## 9. 状态文件与限制

状态是一个版本化 JSON，保存原始样本快照及其内容指纹、预处理/拟合/选题配置、随机状态、当前待答题、按顺序追加的答案记录，以及最近成功的权重与覆盖数。写入使用**同目录临时文件 + 原子替换**；答案在拟合之前持久化。

**限制：**

- **一个状态文件只运行一个训练进程。** 不支持多个进程同时编辑同一状态。
- 不支持在已有会话中改样本、增补样本、修改答案或重新打开已跳过的题；需要这些时请开启新的状态文件。
- 恢复时若提供 CSV，内容与快照不一致（含价格等必需字段变化）会**拒绝恢复**，不会把旧标签静默套用到新数据。状态版本不支持同样拒绝，且不改写原文件。
- 候选枚举是城市内平方复杂度，面向几十家样本；不在本版做大规模索引。

## 10. 已知限制（请勿过度解读）

- **九档等距假设未经检验。** 档次用单一 `grade - 4` 特征，舒适到高档的比较不能证明奢华档的边际价值也相同。
- **固定曲线是 v1 设计假设**，不是已验证的真实偏好曲线；变更曲线必须提升预处理版本。
- **跨城市迁移尚未验证。** 所有城市共享同一组权重，但本版没有留出城市的评估，也没有城市系数，因此**不能宣称**权重可跨城市通用。
- **相关特征会让权重不稳定。** 采样时尽量寻找属性没有同步变化的酒店，避免把权重当作因果作用或"重要性百分比"。
- **诊断中的训练交叉熵只表示训练拟合程度**，不含正则项，**不是校准度、验证误差或泛化精度**。
- 若某个特征在所有有效比较中差值恒为零，诊断会提示该维度**缺少比较信息**；此时权重接近零不代表"用户不在意"。
- 主动选题会带来选择偏差；20% 随机探索只是缓解，不消除。
- 本版假设**单个人、稳定的旅行偏好**；不同出行目的会改变取舍。

## 11. 开发与测试

```bash
conda run -n hotel-model python -m pytest
```

测试覆盖数据校验、v1 特征、标签方向与梯度、约束拟合与失败处理、候选与主动选题、状态指纹与原子写入、恢复校验、终端训练循环与诊断。
